# Prospective Google event automation — 2 November 2026

Automatic Google event mirroring now uses the existing physical automation queue and managed worker. Canonical interview create/reschedule/state/reminder transactions append a durable `google_calendar_sync` task for the current event fingerprint when the owner has enabled this policy. There is no parallel scheduler, cron, sender or provider polling loop. No migration, dependency or new environment key is required. Policy lives under a dedicated `workspaceSettings.policyConfig.calendarAutoSync` namespace; unrelated settings are preserved.

Control Plane exposes enable/pause, policy revision, worker/emergency-stop guidance and recent task outcomes. Only the owner can change this policy. It defaults off. Enabling applies to subsequent saved changes, with no existing-record backfill. Pausing this policy stops new enrolment and invalidates older tasks; re-enabling creates a new authority revision. Pausing only the managed worker retains queued changes for resume. Reconnect or target-calendar changes invalidate authority and require re-enabling, preventing silent copies into a different calendar.

Tasks bind owner, authority revision and exact event preview. Old interview snapshots complete as cancelled without provider writes. Shared queue claiming and connection leases serialize workers; deterministic Google IDs recover unknown create outcomes. Provider quota/transport failures have bounded exponential retry (five attempts); auth failures, external edits, stale authorities and uncertain worker leases block/cancel for review. In-flight writes cannot be recalled after Google accepts them; a pause or local edit received during provider HTTP can require reconciliation. Unknown update outcomes can block on ETag divergence rather than blindly overwrite.

Every Google write rechecks automation authority at provider-write boundaries. Calendar events contain generic references, saved times/timezone and meeting URL. No guest attendees/invitations are sent (`sendUpdates=none`). This does not create Google Meet links, negotiate participant availability, reserve interviewer time or ingest Google-side edits/RSVPs. External edits are preserved and block subsequent writes. An in-app conflict-resolution/override workflow remains pending; blocked tasks require review, not automatic overwrite. Manual reviewed sync remains available for ordinary operations but is also subject to ETag protection.

Verification covers default-off, required connection/worker, no backfill, settings CAS, policy isolation, shared-queue reschedule/cancel, stale task cancellation, pause/in-flight fencing, target changes, quota retry/backoff, managed-worker pause/resume and concurrent SQL claims. Actual provider mutation responses are synthetic in tests. Production readiness and UI are checked separately; mocked event writes must not be described as actual Google event verification.
