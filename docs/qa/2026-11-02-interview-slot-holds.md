# Internal interview slot holds — 2 November 2026

Owners can create a short-lived internal candidate slot hold, release it or convert it into a saved interview from Interviews. A hold lasts 1–30 minutes, is capped at the proposed start, and accepts future slots within 90 days. Expired holds stop blocking immediately using the server clock; no timer, cron or worker must run to release them. The UI counts down and refetches state. These are internal candidate holds, not Google calendar reservations, interviewer/panel availability or participant acceptance. No invitation or provider event is sent by a hold.

The existing workspace transaction serializes hold creation, direct interview scheduling, rescheduling, state reactivation, release and booking. The canonical scheduler creates the interview, calendar UID, audit and reminder configuration; the same SQL transaction consumes the hold. A failed final audit rolls everything back. Half-open intervals permit adjacent times. Workspace ownership and candidate withdrawal/deletion checks apply. Existing team-role permissions are not expanded; the new hold procedures are owner-only under current RBAC.

Request identity is bound to hold content. Retries preserve original expiry and cannot resurrect expired/released holds. Booking retries bind job/client/meeting details and return the original interview even after cancellation, rather than recreating it. Another booking of the same time or another overlapping hold is rejected. Holds and interview conflicts appear together in the schedule preview. Preview is point-in-time and does not itself reserve anything.
