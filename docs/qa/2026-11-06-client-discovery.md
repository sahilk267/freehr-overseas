# Scoped client discovery collection and tentative booking — 6 November 2026

A reviewed “Arrange discovery call” action on the current permitted client reply can open a discovery request with explicit recruiter windows, duration, buffer, expiry and an optional per-request earliest-slot authorization. The default is owner selection. Dedicated `clientDiscoveryRequests` and `clientDiscoveryMeetings` tables separate clients from candidate interviews. No candidate, requisition, commercial acceptance or attendance record is invented for a discovery meeting.

The existing shared availability intersection/ranking algorithm and buffered Google free/busy reader produce proposals. A canonical internal busy reader includes recorded owner interviews, active holds and discovery reservations. Discovery reservations also participate in interview previews, proposals, new holds, scheduling and rescheduling. Reservation admission uses the same workspace transaction lock: different client requests cannot reserve the same recruiter slot concurrently. Meeting buffers protect adjacent reservations. Past meeting history does not permanently prevent a new request.

A private fragment capability is shown once at creation; only its hash is stored. Owner history and exception lookups never return tokens. The public POST endpoints use no-store/referrer headers, return only scheduling context and check current reply/action/recipient/permission, token and expiry under the owner lock. Exact response retries reuse their revision; changed submissions reject. A submitted response is availability evidence, not verified identity, attendance or commercial acceptance. Quoted discovery capabilities are redacted from inbound storage/AI context by the existing shared redactor.

No suitable slot produces one existing-format owner incident with navigation back to the client thread; cancellation resolves it. Manual selection goes through the same booking command.

One immutable booking belongs to each request. Exact booking replay returns the recorded meeting, including its cancelled status, and cannot recreate it. Cancellation revokes the capability, queued selection and local reservation together.
