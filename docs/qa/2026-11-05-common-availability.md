# Common availability proposals — 5 November 2026

Interviews now proposes up to ten common slots from owner-entered candidate and interviewer availability. Each participant has a separate timezone input, interpreted using the existing DST-aware conversion helper. The proposal service normalizes overlapping/duplicate windows, intersects both participants, rounds starts to a five-minute grid, excludes elapsed time and Google busy periods, and applies a configurable 0–60 minute buffer. Duration is bounded to 15–240 minutes; participant windows fit within 31 days. Busy queries include the boundary buffer and fail closed when the expanded window exceeds the provider's 31-day limit or Google cannot verify availability.

The API accepts up to 100 windows per participant, while the initial form accepts one window each. It uses the existing owner-only Calendar router, private no-store responses and existing Google token/lease/free-busy adapter. No new provider, credential, database schema or scheduling engine is introduced. No common time means no proposal; provider failures never become a free-slot result.

This is a proposal capability, not completed two-sided negotiation. Windows are reported/entered by the owner, not authenticated participant submissions. It does not check existing candidate records/internal holds, interviewer calendars beyond the connected owner's calendar, business-hour policy, panel requirements or participant acceptance. It does not reserve, create an interview, send links/invitations, or change Google events. The UI directs the owner to the existing candidate schedule check and internal hold before booking. Secure participant availability links and the confirmed-booking workflow remain pending.
