# W19 — read-only policy lab and recorded approval/job inspection

14 November 2026 (Asia/Calcutta). Partial **M04-F08 / M22-F02**. No whole module is complete.

## Implemented

- The private `/policy-lab` page compares actual workspace configuration, an owned saved policy version or unsaved bounded JSON against a hypothetical action/payload or an owned stored approval. Stored subjects forbid action/payload overrides. Saved comparisons do not activate a policy; an exact stored-content digest distinguishes them from current workspace configuration. An explicit refresh clears results and preserves drafts. Edited inputs mark prior results outdated.
- The live first-match predicate and the diagnostic path share one implementation. Traces distinguish action mismatch, invalid conditions/operators, missing own fields, numeric type mismatch, failed conditions and empty unconditional rules. They show field/operator/type/reason, never actual/expected values or stored approval payloads. A first failure stops condition evaluation; a first match stops rule evaluation. At most 100 visited rule traces and 50 evaluated condition traces per retained rule are returned; later evaluation still determines the actual first match. Omitted evaluated conditions and unvisited conditions are distinct.
- Live predicate hardening rejects inherited payload fields, nonfinite scalar operands and malformed payload shapes. Nonfinite default grace falls back to the existing 15-minute default. Valid persisted JSON rule ordering/operators and grace precedence are preserved. Inherited object-property names cannot resolve as canonical actions. The executor and lab reuse the same supported side-effect set rather than separate registries. Existing legacy `email_send` policy matching remains distinct from canonical mandatory human gates. A matching rule cannot override those gates, or turn an unsupported action into an executable effect.
- Owner-only catalog/inspection reuses canonical workspace settings, policy versions, approvals and queue records. It returns minimized approval metadata and the latest 20 matching recorded policy-job schedules/states/attempt counts with explicit action/resource scope comparison. Raw payloads, reasons, queue errors and policy configuration values are withheld. Only the latest 50 saved versions are listed, with an older-version flag. Owner source sets above 10,000 rows fail closed instead of giving partial source totals. JSON inputs have byte, depth and node bounds; unsupported stored shapes also fail closed. Catalog approval filtering/pagination includes cancelled records.
- Rule-level/configured grace is hypothetical; recorded job schedules are displayed separately. Mode, emergency stop, background status and the existing workspace contact-window calculation are contextual observations. No recipient window, consent, suppression, quota, evidence, resource-version or provider-readiness check is certified. No quiet-hour exception is granted. Registered intent is explicitly not a preview of the exact current domain effect.
- Both endpoints use the existing owner/workspace authorization barrier and private no-store/no-referrer responses. Team roles receive no new permission. No schema, environment variable, secret, credential, approval authority, policy activation, job, alternate decision engine or external effect is introduced.
