# Interview panel evidence, corrections and feedback reminders

Date: 12 November 2026 (Asia/Calcutta). Scope: M18-F05 with existing employer criteria, feedback rows, follow-up/outbox, matching and privacy. No entire advanced module is complete.

## Behavior

- Owner-configured versioned panels bind the exact owned interview schedule and current job rubric. Criteria must be valid employer weights totaling 100%, reviewer keys/contact assignments are unique, and linked contacts must belong to the exact client. Processing permission, candidate suppression, company/role availability, source changes and future deadlines are checked. Panel evidence is explicitly owner-recorded, not independently authenticated client identity.
- Structured responses are stored in the existing feedback table. Numeric 0–5 ratings require literal supporting quotations from the recorded job-related feedback; unknown stays unknown. A completed past interview with its completion time is required. Exact request retries return the same receipt. A new request key cannot create a second active response for the same reviewer; corrections name the exact active predecessor and preserve older observations.
- The first observation does not declare the entire panel complete. Missing reviewers, missing criterion evidence and differing ratings remain visible, with ranges rather than an invented average/consensus. A spread of two or more points is an explicit review flag. Owner next-action records bind the exact current response set and distinguish clarification, owner review and consideration of another round. Missing reviewers prevent next-round consideration. These records do not book a new interview, authenticate a client decision, reject/advance a candidate or bypass consequential approval.
- The canonical legacy raw-feedback route refuses new unscoped records once a panel governs the interview. No duplicate feedback/profile/decision table is introduced. Panel/response/next-action activity invalidates existing candidate-job matching context. Bounded model context labels the latest updated panel, includes source references and missing reviewers, and remains identity-unverified with no final disposition.
- Assigned reviewer conversations are prepared/reused for the exact client/contact/job without sending mail. FU20 uses a reviewer-bound `interview_feedback` resource in the existing M06/M05/M07 engine. Source revision, response, deadline, processing/contact permissions, opt-out, recipient, sender and resource scope are rechecked before preparation/send. Existing outbound approval, frequency, quiet-hour, budget and uncertain-delivery guards remain authoritative. Recording a response cancels that reviewer's unused reminders; a new panel stops old plans. No second sender, timer or worker is introduced.
- Owner Interviews includes panel setup, exact criteria, reviewer observations/corrections, comparison, next-action review, history and shared reminder controls. The next-action form preserves an explanation while requiring explicit review of a changed response snapshot. The existing raw form remains for legacy ungoverned interviews; governed records direct the owner to the panel.
- Candidate erasure now includes canonical feedback rows, both structured and historical unstructured text, source/identity/review events and client-thread feedback reminders. The helper stops unused mail authority before redacting source content. Physical-document deletion failure retains the existing privacy investigation behavior.
