# Candidate evidence, compensation, ranked pools and current AI scoring

Date: 7 November 2026 (Asia/Calcutta). Target: `https://freelancehr.overseasjob.in`.

## Delivered scopes in this batch

1. **Candidate evidence profile:** owner-recorded skills, relevant experience, permitted work models/locations, explicit compensation amount/currency/pay period, notice and availability, observation/expiry, source reference and review reason. Immutable ledger revisions use optimistic fingerprints and exact retry identity. Statements expire within 180 days and remain explicitly not independently verified. Saving does not grant consent or reactivate suppression. No new schema or parallel candidate profile is introduced; legacy profile data remains separate and unverified when units are absent.
2. **Recorded compensation comparison:** compare explicitly stated amounts in the same currency. Monthly and annual amounts use ×12; equal hourly/daily periods compare directly. Unknown units, legacy default currency, differing currencies or hourly/daily conversions remain unknown. No FX, work hours, tax, benefits, bonuses or market-feasibility assumptions are introduced. Budget conflicts request review rather than reject a candidate.
3. **Explainable ranked review pool:** inspect a bounded owned-candidate page, exclude suppression by flags and state, identify exact mandatory-skill evidence, experience/work-model/location/availability conflicts and missing facts. Retrieval priority uses fixed 70/20/10 components for skill coverage/minimum experience/recorded budget compatibility, capped at 50 without a current owner statement. This is not the employer's weighted scorecard or a hiring disposition. A missing skill is missing evidence, not proof of absence. Extra experience above an employer maximum is not penalized. Each inspected page ranks independently, with scanned/suppressed counts and explicit next-page coverage; this is not a globally complete pool ordering. Reviewed pool snapshots are private and historical, with stable identity and current-preview-hash admission.
4. **Shared current AI scoring:** per-pair and selected-pool scoring use one context builder and canonical queue command. Batch actions accept at most 20 selected candidates and atomically save the snapshot/queue work. Identical work reuses the same existing queue task. Valid current processing consent is required. Candidate statement/document/consent and job fingerprints are checked before inference and before result application. Oversized AI input is explicitly rejected rather than sliced silently. Required deterministic missing/conflict evidence persists even if the model claims perfect confidence. Legacy unbound results remain review-only. No sender, timer or second scoring engine is created.

## Lifecycle integration

Candidate evidence edits mark active matches for review without reopening closed/withdrawn matches or moving a shortlist backwards. Current scores also preserve shortlist progression. Closed pair history cannot be reopened by automatic rescoring. Existing statutory erasure redacts the new evidence ledger and removes the candidate's row from historical ranking snapshots; candidate tombstones prevent late reads/writes. No new candidate/job FSM states or automatic final rejection are introduced. Current rank flags and historical snapshots do not authorize contact, sourcing, sharing, interviews or offers.

The builder includes a bounded clean parsed-document context (20 document identities in the fingerprint, at most 3 document bodies sent to AI). Different experience statements produce a conflict; this does not establish timeline reconciliation or semantic truth. A current owner statement takes precedence for listed skills, while parsed document evidence remains visible to the AI as untrusted source evidence. A model request that exceeds the provider's input limit must be compacted/reviewed explicitly.
