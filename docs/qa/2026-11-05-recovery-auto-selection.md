# Scoped automatic recovery selection — 5 November 2026

An owner can authorize one bound recovery request to choose the earliest suitable shared slot. The authorization fixes duration, buffer, minimum notice and an absolute horizon end, as well as the current interview occurrence and selected Google calendar generation. It is disabled by default and does not transfer to a replacement request or a new decline cycle. The owner widget shows revision/task outcome, explicit bounds and pause controls.

Configuration and durable task creation commit together through the existing event ledger and physical queue. Exact configuration retry cannot create a second task; stale changes reject. The deterministic task uses the same proposer and canonical booking/reschedule command. Saving a different time preserves the interview ID, closes capabilities and records automatic execution with a cron actor and policy revision. It does not assert participant acceptance; both participants must confirm the new time separately.

Pending responses defer without spending provider reads or retry attempts. Policy revocation, candidate/job/resource changes and calendar generation changes cannot authorize a newer occurrence. Worker pause/stop before claiming leaves the task queued; pause during provider I/O defers it and all checks repeat after resumption. Notice/horizon, policy and response checks repeat before fresh provider reads and within booking commit. Provider/transient conflicts use bounded shared-queue retries. Immutable booking evidence prevents retry from recreating a cancelled appointment.

Shared proposals now exclude recorded candidate interviews and active holds before ranking. The same internal readers still guard booking. A 31-day window plus buffers uses at most two bounded Google reads, preserving calendar generation and the oldest check timestamp. No second proposal engine, timer, sender, grant store or migration is introduced.

No suitable slot creates a terminal owner-review outcome. Its incident uses the same recovery identity as later deadline escalation, so expiry updates the existing incident. Owner reauthorization, replacement, reschedule and cancellation resolve the owned issue through shared helpers. Changing windows after a no-slot terminal result requires renewed owner authorization.
