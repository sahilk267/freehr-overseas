# Scoped discovery Google Calendar lifecycle — 6 November 2026

Client discovery now adapts the existing Google Calendar write engine, connection/refresh lease, preview/review, deterministic event identity and ETag checks. Interview snapshots and existing binding rows remain compatible. Discovery uses a separate resource namespace and the existing immutable workflow ledger for binding observations; no candidate interview, credential store, provider sender, scheduler, timer or migration is added.

Discovery sync is off by default. A new request can explicitly authorize mirroring its eventual meeting and cancellation to the currently connected calendar. This grant is recorded in the same request transaction and inherited only by its one canonical booking while the connection generation still matches. Existing meetings can instead enable a per-meeting policy after a fresh owner event preview. Exact retries reuse the policy/task; disable, account/calendar-generation changes and stale local versions fence old tasks. The existing interview auto-sync setting cannot authorize discovery events.

Canonical booking and cancellation enqueue `google_calendar_sync` tasks into the same persistent worker. Pause/stop before claiming preserves work; a pause during provider activity defers current unchanged intent without resetting authority or creating another event. Source/version or policy revocation supersedes the old task. Event creation is private, tentative and contains no client/candidate identity, attendees or conferencing data; default Google reminders are disabled and every write uses `sendUpdates=none`. Calendar sync does not prove attendance or commercial acceptance.

Stable event IDs prevent duplicate creations after retries or a lost response. A confirmed POST response records its owned event/ETag observation before a later resource-version fence. Thus a concurrent local cancellation has proof to reconcile the known creation. A lost response may adopt an unchanged, matching owned event; if the remote fields changed before that first binding was persisted, it requires current owner review. Normal external edits and If-Match races also stop automatic replacement. Owner conflict review binds the current local preview and exact remote event/ETag; unrelated identities cannot be overridden.

The owner panel exposes event preview, scoped enable/pause, manual reviewed sync, external-change review and recent managed task results. The prospective request checkbox is separate from automatic slot selection. Existing private-link mail, calendars and interview APIs reuse their previous mechanisms. No historical discovery meeting is silently backfilled.
