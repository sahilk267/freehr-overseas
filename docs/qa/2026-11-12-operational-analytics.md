# Source-linked operational recruiting analytics

Date: 12 November 2026. Scope: partial implementation of M23-F01/F02/F03/F04/F06. M23-F05 controlled experiments remains planned; no complete advanced module is claimed.

## Implemented behavior

- Owner-only `/analytics` and `analytics.report/options/export` reuse canonical recruiting, invoice/payment, follow-up, audit, event, queue and AI usage rows. Read-only transactions select calculation fields rather than names, bodies, recipient addresses, private task errors or unbounded provider metadata. No new schema, secret, worker, financial authority or automated decision is introduced. API reads use private/no-store caching; report responses use no-referrer.
- Distinct current inventory and period-created placement cohorts use explicit half-open dates, IANA grouping timezones and a maximum 366-day period. Cross-owner sources never enter totals. Exact client/role/placement relationships are checked; duplicate identities are deduplicated, conflicting copies fail, and missing/future timestamps remain visible. Filtered workflow counts include only explicit source links, so generic candidate/workspace work is not silently assigned to a role.
- Finance preserves per-currency integer minor units with BigInt accumulation and exact display. Canonical succeeded receipts, live provider-verified subsets, period-posted flows, open/overdue/disputed receivables, overpayments and noncollectible residuals remain distinct. Provider proof requires the matching live checkout request, observed receipt and exact canonical allocation. Manual paid status, replayed events, sandbox results and unmatched observations do not promote proof. Wrong-currency/orphan rows are quarantined. No bank-clearing ledger exists: cleared cash, measured cost and contribution margin remain null/unavailable.
- Placement outcomes share one distinct placement-created denominator, with separate recorded acceptance, email-possession receipt, owner-approved joining and exact invoice/receipt evidence. Zero denominators produce unavailable percentages. These are current outcomes for a placement-record cohort, not a historical lead-to-hire causal funnel. Revoked/erased evidence is not reconstructed from retained analytics snapshots.
- Follow-ups preserve physical acceptances and deduplicate logical plan/revision/step identities. Explicit RFC reply references take precedence over a bounded latest-prior acceptance in the same thread; unmatched references and ambiguous timestamps receive no credit. Each inbound associates once. Mature response windows and open windows have separate denominators. `createdAt` measures ingestion, not independently verified arrival: historical imports can affect association. Rates are descriptive, not causal lift. Recipient fatigue exposes aggregate claim-stamped counts only, not hashes; complaints/personas remain unavailable.
- Completed stage intervals require two consistent, strictly ordered audit transitions; current age requires a matching unambiguous last transition. `updatedAt` and creation time never substitute for missing entry evidence. Current queue lag, retry counts, stale leases, pending approvals/incidents and period model attempts/latency are observations only. Model factuality, monetary cost, calibrated ranking and effort saved require measured baselines and remain unavailable.
- Versioned definitions, source digest, integrity issues, searchable client/role filters, cohort chart, source drilldown and full bounded CSV support owner review. CSV values are quoted/formula-neutralized. Export recomputes sources and returns conflict if the digest changed. The preview explicitly shows at most 50 rows; export contains the complete bounded section. Sources above 10,000 rows per business table or 30,000 relevant events/audits fail closed; this is not a historical warehouse.
