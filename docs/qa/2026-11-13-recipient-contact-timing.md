Date: 13 November 2026 (Asia/Calcutta). Scope: partial M06-F06 with shared M07 delivery, M04 privacy and owner controls. No entire advanced module is complete.

## Behavior

- Owner Follow-ups adds a quoted inbound-source timing review. The source must be a received, non-future record in the exact owned recipient thread; its literal quote and body hash are retained as owner-recorded evidence. Corrections use optimistic revisions and append-only history, with exact retries reused. Recipient identity and natural-language date interpretation remain independently unverified. The server does not infer an out-of-office return date with an LLM.
- Return holds, IANA timezone, optional daytime/overnight window, local weekdays, preferred channel, recorded language and review expiry are scoped to the same normalized recipient email within the workspace. Address changes do not transfer restrictions. Review expiry is bounded to 90 days; a return date must precede expiry. Empty/invalid windows fail. Expired or malformed active evidence blocks contact pending review instead of silently disappearing. Explicit retirement requires current revision and a reason.
- The existing canonical delivery transaction reads current timing under the shared workspace admission lock. The next allowed time intersects return holds, recipient windows and current workspace/plan quiet-hour/weekdays policy. Daylight-saving and overnight boundaries use the existing IANA clock helper. Minimum-spacing and daily-budget recalculation reapply recipient constraints so they cannot shorten a return hold or spill outside a preferred window. Unsupported preferred phone/SMS/WhatsApp channels withhold agency email; this does not invent an adapter or grant another channel permission. Language is recorded for owner/template review; no automatic translation is claimed.
- Deferred work uses the existing dispatch/task identity and durable next-action schedule without consuming authorization or contacting the provider. A hold beyond a follow-up deadline cancels that follow-up under the existing gate. Source/consent expiry, suppression, reply pauses, emergency stop, current sender, finite grant budgets and uncertain-delivery reconciliation retain their precedence. Saving/retiring timing does not resume a paused sequence, renew a grant, edit messages or authorize contact. Already admitted provider attempts cannot be recalled. Recipient-requested transactional verification codes keep their exact separately reviewed bounded security exception; invitations and campaigns do not receive it.
- Owner controls show a timing-only preview and source limitations. A concurrent correction preserves the operator draft and requires explicit loading/review of the current restriction before saving. Only the latest 20 received source previews are shown, with explicit truncation. Candidate privacy fulfillment redacts quoted timing/history before later reads can expose an erased subject. APIs default to owner-only access and private/no-store/no-referrer headers. No new schema, API key, sender, timer or consent engine is introduced.
