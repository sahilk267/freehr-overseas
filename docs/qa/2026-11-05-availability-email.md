# Approved availability-link email — 5 November 2026

Pending participant links can now prepare a single email approval through the existing message/approval/dispatch tables and physical queue. The collection panel offers role-matched eligible conversations and active interview-purpose senders. Recipient is derived from the owned conversation rather than supplied freely: candidate/job/permission or permitted client-contact relationships are checked. Preparation replaces that participant's earlier manual capability, with a visible warning. Exact preparation retry reuses the immutable message/approval; changing its target requires a new request.

No raw token or complete private URL is saved in the message or approval. A purpose-separated HMAC envelope uses the stable session secret, random nonce, owner/invite/group/revision, participant, recipient hash and HTTPS application origin. The invite stores only its token hash. Approval content hash binds the envelope using fixed field order, preserving existing hashes for ordinary emails. Dispatch generates the exact scoped URL only in memory. Already-delivered links retain ordinary expiry/revocation after secret rotation; pending envelopes stop when key/origin changes. No new key, sender engine, database table or migration is required.

The shared approval engine and delivery gateway recheck recipient, consent, suppression, sender, link status/revision, expiry and envelope/content binding. Candidate consent checks are extracted into a shared helper used by the existing follow-up engine too. Existing quiet hours, contact caps, emergency stop, claim-once semantics and uncertain-delivery reconciliation remain in force. Approved dispatch is queued through the existing worker. Owner rejection cancels the private message/dispatch and revokes the unchanged pending capability. A send already admitted to provider HTTP cannot be recalled; revoked links still deny subsequent access.

No actual recipient email is sent during QA. Provider-positive sends use a transport stub. This does not verify SMTP delivery/read receipts, participant identity/acceptance, interview confirmation, unattended outreach grants, alternative-window follow-ups or reminders. Link transmission still requires the existing explicit owner email approval; this change does not remove that policy.

Validation: 535 unit tests pass / 30 skip; 251 disposable real-MySQL tests pass across 15 files. Types/build and four hosting entry smokes pass. Tests cover prepare/delivery idempotency, current permissions/addresses, scoped link validity, credential non-disclosure in stored records, envelope tampering, secret rotation, revocation, rejected-draft cleanup, unknown outcomes and simultaneous SQL claims. The initial options test expectation was corrected to match the platform's existing normalized email policy; no new email-case policy was introduced. Live draft/readiness checks are recorded separately and do not represent real provider mail delivery.
