# Owner-reviewed client discovery link email — 6 November 2026

Client discovery extends the existing private-link mail purpose envelope and shared approval/outbox gateway. An owner selects an active client-purpose sender for the request's canonical contact. Recipient, current reply/action/source, permission/expiry, suppression, request status and revision are checked at preparation and again at authorization/dispatch. Candidate and interview-confirmation email formats and signing prefixes remain compatible.

Preparation atomically rotates the earlier manual capability, records only the scoped HMAC envelope/token hash and creates one message, approval and dispatch intent. The draft contains a descriptive marker. The actual `/discovery-response#id.token` URL is materialized only in memory for dispatch; neither its raw token nor URL is stored in the message, approval or audit evidence. The purpose has a separate signing prefix and binds owner, request, revision, recipient, nonce, signing configuration and origin. Exact retries reuse the original email; a different sender/intent cannot fork another send for that request.

The existing owner-review policy remains in force. Pending requests only can receive link email; a response, expiry, cancellation, source/recipient change or revoked permission prevents obsolete mail. Rejection cancels the unused request and dispatch. Request cancellation revokes unused mail authority and queued work through a shared cancellation helper, also reused by follow-up cancellation. Attempted, in-flight and unknown outcomes retain their reconciliation state and cannot be cleared into an automatic resend. Provider acceptance is not proof of recipient delivery.

The discovery panel offers the current recipient, client senders and preparation action, clears the replaced manual link and links the resulting intent to the existing approval queue. No second sender, timer, grant engine or migration is introduced. Schema remains at 24 migrations.
