# Screening clarification, shared reminders and owner-review deadlines

Date: 7 November 2026 (Asia/Calcutta). Target: `https://freelancehr.overseasjob.in`.

## Connected implementation

Owner review can request a targeted clarification on selected existing job-related questions, with an explicit note and current response revision. One immutable child request binds the exact parent response hash/version and current candidate/job sources. An exact retry reuses that child without redisclosing its secret; conflicting requests are rejected. The prior capability, unused reminders, pending unused link email and old deadline tasks are stopped atomically. Up to three follow-on rounds are supported. Public holders see only the selected prompts and note, not earlier candidate answers or owner records. Parent/current source changes and newer responses fence stale commands.

The owner can inspect all five immutable response/correction versions for a selected request. Evidence-review completion can stop collection without adopting any profile facts. It creates/reuses one evidence-pending screening case at confidence zero and does not pass screening, verify identity, reject a candidate or change hiring states. Profile adoption and answer review remain distinct. Expired public capabilities stay denied while the owner can review source-current responses after expiry. Completed/replaced rounds cannot be adopted or reopened. Matching snapshots/queued work and active match confidence are invalidated by changed review activity. Employer assessments quoting a superseded parent questionnaire become stale and reject newly submitted old-parent ratings; historical owner answer records remain available.

Candidate screening/clarification reminders use the existing follow-up engine and FU11/FU13 scenarios with a new resource binding to the review request. The canonical candidate email thread can be opened/reused only for the exact role with current recruitment-communication permission; this does not send email or manufacture consent. Reminder enrollment requires an explicit owner statement that the private link was already shared. Reminders refer to that earlier link; they do not retain or resend capability secrets. Shared preparation/send checks revalidate role/thread, source fingerprints, current capability, communication permission, sender, recipient, suppression, expiry and reply state. Duplicate enrollments reuse the plan. Current response, revocation, clarification and completion stop unused authority; attempted/uncertain dispatches remain available for reconciliation. Per-send review is the default; existing bounded owner grants support delegated sending. No parallel sender or timer engine was added.

New requests enqueue an expiry task, and each response version enqueues a 24-hour owner-review deadline, in the existing durable queue. These deterministic tasks consume no AI quota, respect managed-worker pause/emergency stop and create one source-bound incident for an unanswered expired request or overdue owner review. They do not contact recipients. A newer correction or changed/suppressed source fences older timers. Expiry revokes the public capability; source-current retained answers remain reviewable. Completion/clarification resolves outstanding cases and cancels superseded tasks. Owner incident links navigate directly to the owned candidate/request, including a request outside the ten most recent requests shown in the normal list. Deadline task payloads include the canonical candidate reference so existing privacy erasure cancels/redacts those tasks. Existing review/privacy events and follow-up erasure cover the new metadata. Infrastructure errors propagate as failures rather than falsely marking a source stale.
